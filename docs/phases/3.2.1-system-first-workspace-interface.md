# 3.2.1 — System-first workspace interface

Status: **Approved for implementation — owner approved 2026-10-19; single-view World refinement approved 2026-10-19**

## Goal

Replace the route-tab dashboard shell with a system-first workspace interface in which World is the workspace environment, not a navigation item or a visualization embedded in a card.

## User-visible outcome

Operators enter a full-screen, static and responsive representation of the workspace. Agents, Knowledge, Channels, Conversations and optional Commerce scope appear as parts of that system. Record-heavy work opens as a focused screen with a clear return to the system rather than as another sidebar tab.

## Existing Behavior to Preserve

- Existing authenticated routes and deep links remain valid.
- Server-authorized capability visibility and tenant boundaries remain unchanged.
- Knowledge-only workspaces remain complete without Commerce UI.
- Focused Agent, Inbox, Knowledge, Analytics and Commerce workflows retain their current behavior.
- World remains a read projection of authoritative state.

## Scope

- Replace the persistent sidebar `AppShell` with one workspace route boundary and a full-width system header.
- Make the workspace overview the system home without rendering a World navigation tab.
- Expose Inbox directly and other authorized focused areas through a contextual system launcher and World relationships.
- Render World as one static responsive system view. Do not add redundant projection or time-window controls to the system home; detailed filtering belongs in focused analytical workflows.
- Remove camera, pan, zoom, fit controls, absolute layout coordinates and canvas-like framing.
- Use responsive CSS Grid so Agent count per row follows available width.
- Render the optional business-data rail as part of the full-screen system layout and move it below the Agent field at narrower widths.
- Open selection detail as an overlay/drawer so it does not resize the system layout.
- Move workspace identity/capability loading to the route boundary and stop feature pages from independently wrapping themselves in a shell.

## Non-goals

- Renaming or removing existing routes.
- Replacing record-heavy focused screens with graph editing.
- New persistence, APIs, domain behavior or dependencies.
- Fake or speculative domain data.

## Confirmed Decisions

- World is the workspace interface, not a sidebar item.
- The workspace UI has no persistent left sidebar.
- Static responsive layout replaces spatial camera interaction.
- The system home begins directly below the global header without a page hero, duplicate heading or shallow filter toolbar.
- Existing focused routes remain accessible but are presented as focused modes of the system.
- Capability visibility remains server-derived.

## Schema Impact

None.

## API Impact

None. Reuse the existing workspace overview projection.

## Frontend Impact

- Add a workspace route layout/provider and system shell.
- Remove `AppShell` usage and obsolete World layout machinery.
- Update responsive styling, shell tests and World tests.

## Security Impact

No authorization moves to the client. The shell displays only server-authorized capabilities and existing focused routes continue enforcing their own access rules.

## Test Plan

- Verify one workspace identity/overview load at the route boundary.
- Verify no World navigation tab or sidebar exists.
- Verify no duplicate World heading, projection switch or time-window switch exists.
- Verify capability-aware launcher behavior and focused-screen return navigation.
- Verify Knowledge-only and Commerce-enabled World states.
- Verify responsive Agent grid and business rail behavior at 1440, 1024, 768, 390 and 320 pixels.
- Run relevant component tests and TypeScript typecheck.

## Documentation Impact

Update the current implementation section of `docs/ui.md` after implementation.

## Acceptance Criteria

- World begins directly beneath the global header, fills the workspace viewport and is not enclosed in a dashboard card.
- Agent units flow into a responsive grid with no authored coordinates.
- The persistent sidebar, camera controls and canvas-like interactions are absent.
- All implemented focused workflows remain reachable and deep links remain compatible.
- Knowledge-only and Commerce-enabled workspaces show only real authorized data.
- Keyboard, screen-reader and mobile access remain available.

## Blocking Owner Decisions

None. The owner explicitly approved replacing the prior AppShell/navigation boundary on 2026-10-19.
