# M1.2 Facebook connection and verified webhook

## Goal

Close the M1.1 PostgreSQL migration rehearsal gate, then deliver the first M1.2 slice:
tenant-scoped Facebook Page connections and authenticated inbound text webhooks over the shared
channel foundation.

## Acceptance criteria

- A PostgreSQL opt-in test upgrades to `20261005_0013`, seeds existing Website channel/session/
  conversation/message data, upgrades to `20261006_0014`, verifies every backfill including
  message direction, and downgrades to `20261005_0013` without data loss.
- Owner/admin can connect a Facebook Page to a published agent revision. The Page token is
  validated server-side, stored only in the credential vault, and never returned or logged.
- Connection reads expose safe lifecycle/health state; revoke disables processing and removes
  the vaulted credential.
- Webhook challenge requires the configured verify token. POST delivery reads a bounded raw
  body, verifies `X-Hub-Signature-256` with the Meta app secret before any connection lookup,
  then normalizes supported text messages into the shared channel service.
- Duplicate and reordered deliveries do not duplicate normalized messages or paid work.
- Unknown, revoked, cross-workspace and invalidly signed requests fail safely without exposing
  tenant state.

## Confirmed decisions

- Use official Messenger Platform HTTPS webhooks and Graph API; do not use Messenger MQTT or
  reverse-engineered consumer sessions.
- Use Supabase Vault for production Page credentials. Supabase owns the per-project root key;
  `channel_connections` stores only the returned Vault UUID. Restrict database access to
  `vault.decrypted_secrets`, and include the Vault root key in backup/restore runbooks.
- Keep the Graph API version explicitly configured so upgrades are deliberate.
- This slice persists verified text only; it does not invoke outbound delivery or add UI.

## Data, API, UI and security impact

- No application-table migration is expected; M1.1 already contains connections, bindings,
  webhook events and normalized conversation mappings.
- Add authenticated connection-management routes below
  `/api/v1/workspaces/{workspace_id}/channels/facebook` and public GET/POST webhook routes below
  `/api/v1/webhooks/facebook`.
- No dashboard UI change.
- App secret and webhook verify token remain server-only configuration. Page access tokens are
  stored with authenticated encryption in Supabase Vault and responses contain no credentials.

## Test plan

- Run the isolated PostgreSQL migration rehearsal against the configured non-production DB.
- Unit-test challenge, bounded raw-body handling, signature verification and payload parsing.
- API-test owner/admin authorization, cross-workspace denial, token validation, safe responses,
  health and revoke behavior using fake Graph and Vault adapters.
- Test valid, invalid, duplicate, reordered, unknown-page and revoked-page webhooks.
- Run backend Ruff, mypy and relevant pytest suites; run offline Alembic SQL as a regression.

## Documentation impact

- Record the credential-vault/key-management decision and provider transport/configuration in
  the authoritative channel, security, API, operations and testing documents as applicable.

## Out of scope

- Attachments/media download or quarantine.
- Outbound Graph API delivery and delivery-status webhooks.
- Reauthorization UX, message-window/opt-out enforcement and unified inbox UI.
- Live paid/provider calls or automated Meta App Review flows.
