# F3.1 — Agent foundation and catalog tools

## Status

Implemented. This ADR records the approved F3.1 slice only; it does not authorize F3.2+, publishing, widget sessions or model calls.

## Decision

- `agents` is workspace-owned with a BIGINT internal key and globally unique UUIDv7 `public_id`.
- Core draft configuration is stored as validated columns: name, greeting, safe instructions and locale. Provider/model configuration and immutable published revisions remain later work.
- Location and collection authorization use independent all-vs-selected modes. API `null` means every active resource in that dimension; an empty list means no allowed resource. New agents default to all catalog resources inside their own workspace.
- Selected assignments use `agent_locations` and `agent_catalog_collections`. Both carry `workspace_id` and composite foreign keys to the agent and assigned catalog resource, so a cross-workspace join is invalid at the database boundary.
- A trusted resolver converts persisted assignments into frozen `AuthorizedCatalogScope` sets. Archived/inactive assignments remain persisted but are excluded from runtime authorization.
- Query intent can only narrow these sets. It cannot choose another workspace or add an unassigned location/collection.
- `AgentCatalogTools` maps typed inputs to the existing `CatalogReadService`; it does not implement catalog SQL or accept a dashboard `User`.

## Tool contract

F3.1 provides internal `search_products`, `get_product_detail` and `check_stock` calls. Results preserve:

- generic option/attribute data and same-variant filtering;
- effective location price fallback and exact decimal values, including zero;
- explicit in-stock/out-of-stock/unknown states and nullable quantity;
- inventory policy and update time;
- compatibility-only color/size projections derived from generic options first;
- images as opaque catalog image IDs and safe metadata without Storage object keys, signed URLs or recorded remote URLs.

Candidate products are limited before bounded hydration of variants, options, images and size guides. No per-variant query loop is introduced.

## API and roles

Authenticated workspace routes list/create/read/update agents and atomically replace catalog scope. Owner/admin may mutate; members may read. Cross-workspace resources return non-leaking 404 responses. Agents are created as drafts, and no endpoint in F3.1 can publish or pause one.

## Consequences

- F3.2–F3.4 can reuse one immutable catalog authorization boundary for ingestion, retrieval and orchestration.
- F4 must still define a separate public product-card DTO and authorized image-delivery path.
- Deactivating an assigned location/collection immediately removes it from the resolved runtime scope without deleting assignment history.
