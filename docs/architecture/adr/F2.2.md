# F2.2 — Workspace Catalog, Locations và Collections

## Mục tiêu

Mở rộng catalog của F2/F2.1 để hỗ trợ đúng mô hình doanh nghiệp thực tế:

- Catalog thuộc workspace.
- Một workspace có thể có nhiều chi nhánh/location.
- Nhiều location có thể cùng bán một sản phẩm.
- Một location có thể chỉ bán một phần catalog.
- Cùng một variant có thể có tồn kho và giá khác nhau theo location.
- Không duplicate product chỉ vì sản phẩm xuất hiện ở nhiều chi nhánh.

Domain model phải đủ tổng quát cho nhiều ngành, không hardcode theo shop thời trang.


# 1. Ownership model

Chốt hierarchy:

Workspace
│
├── Master Catalog
│   ├── Products
│   │   └── Variants
│   └── Collections
│
└── Locations
│   ├── Location A
│   ├── Location B
    └── Location C

Nguyên tắc:

- Product thuộc workspace.
- Variant thuộc product.
- Product/variant KHÔNG bị duplicate theo location.
- Location chỉ định product/variant nào được bán tại location đó.
- Inventory thuộc location + variant.
- Giá mặc định thuộc variant.
- Location có thể override giá variant.

# 4. Product availability theo location

Không duplicate product:

SAI:

Product A - HCM
Product A - Hà Nội
Product A - Đà Nẵng

ĐÚNG:

Product A
└── Variant A1
    ├── HCM
    ├── Hà Nội
    └── Đà Nẵng

Tạo relation ở variant level:

location_variants
- location_id
- variant_id
- is_active
- price_override nullable
- compare_at_price_override nullable
- metadata_json
- created_at
- updated_at

Unique:
(location_id, variant_id)

`is_active = false`:
location không bán variant đó.

Một product được coi là available tại location nếu location có ít nhất một active variant của product đó.

Không cần duplicate `location_products` trong F2.2 trừ khi xuất hiện requirement thật sự cần metadata cấp product riêng theo location.


# 5. Inventory model

Tồn kho không còn thuộc trực tiếp `product_variants`.

Không dùng lâu dài:

product_variants.stock_quantity

Source of truth mới:

inventory_levels
- location_id
- variant_id
- quantity nullable
- updated_at

Unique:
(location_id, variant_id)

Semantics phải giữ nguyên:

quantity = null
→ chưa biết tồn kho

quantity = 0
→ đã biết và hết hàng

quantity > 0
→ còn hàng

Ví dụ:

Variant POLO-RED-M

HCM
quantity = 15

Hà Nội
quantity = 4

Đà Nẵng
quantity = 0

Không cộng dồn tồn kho thành một field duy nhất trên variant trừ khi API/query đang cố ý tính aggregate.


# 6. Pricing model

Variant giữ semantics giá mặc định hiện có:

`product_variants.price_override`, fallback về `products.price` khi null.
F2.2 không rename các cột giá hiện hữu.

Location có thể override:

location_variants.price_override

Effective price:

if location_variants.price_override is not null:
    effective_price = price_override
else:
    effective_price = coalesce(variant.price_override, product.price)

Tương tự với compare_at_price.

Không duplicate toàn bộ price record nếu location sử dụng giá mặc định.

# 8. Ranh giới với F3

F2.2 không tạo bảng `agents`, `agent_locations` hoặc `agent_catalog_collections`.
Agent, các assignment và effective agent catalog scope thuộc F3. F3 phải tái sử dụng
location/collection-scoped search của F2.2 thay vì tạo một catalog riêng cho agent.


# 9. Search semantics

Catalog search phải luôn bắt đầu bằng workspace boundary.

Base condition:

product.workspace_id = current_workspace

Sau đó áp dụng các filter location/collection được API caller đã xác thực lựa chọn.

Ví dụ:

"Có váy đỏ size M dưới 1 triệu ở chi nhánh HCM không?"

Search cần resolve:

workspace
+
location
+
collection nếu có
+
product/category
+
variant options
+
effective location price
+
location inventory

Location và collection ID luôn được kiểm tra thuộc current workspace.


# 10. Multi-location query

Workspace có thể query nhiều locations để hiển thị availability.

Ví dụ:

"Áo này còn ở đâu?"

Variant POLO-RED-M
- HCM: 15
- Hà Nội: 4
- Đà Nẵng: 0

API chỉ trả location thuộc workspace đã được authorize.


# 11. F2.1 import interaction

F2.1 tiếp tục import master catalog.

product-scoped:
- product_id
- name
- description
- category
- brand
- product metadata

variant-scoped:
- sku
- barcode
- options
- weight
- variant image
- base price
- generic variant attributes

Không tự hiểu product_id là location identity.

Nếu file import có location-related columns như:

product_id
variant_id
location
stock
price

thì importer phải tách:

Master catalog:
Product
└── Variant

Location data:
Location
└── Variant availability
    ├── inventory

Không tạo một product mới cho mỗi location.


# 12. Import location resolution

Location trong file phải được resolve explicit.

Ưu tiên:

1. location_id / location_code đã có mapping đáng tin cậy
2. explicit mapping do user chọn trong import preview
3. nếu không resolve được → validation/mapping issue

Không silent-match location bằng heuristic mơ hồ.

Không tự tạo location mới chỉ vì gặp một chuỗi chưa biết nếu user chưa xác nhận.


# 13. Migration từ F2 hiện tại

Nếu F2 hiện đang có:

product_variants.stock_quantity

thì F2.2 phải migration an toàn.

Tạo một default location cho workspace khi cần migrate dữ liệu hiện có:

"Default location"

Sau đó:

product_variants.stock_quantity
→ inventory_levels(default_location, variant)

Giữ đúng:

null → null
0 → 0
N → N

Sau migration:

inventory_levels trở thành source of truth.

Không giữ hai source of truth song song lâu dài.


# 14. Existing price migration

Giá product/variant hiện tại được giữ nguyên tên cột và semantics.

Không cần tạo price override tại default location.

Chỉ tạo `location_variants.price_override` khi location thực sự có giá khác.


# 15. Authorization / tenant isolation

Mọi entity mới bắt buộc nằm trong workspace boundary.

Không được:

- workspace A đọc location workspace B
- workspace A attach product workspace B vào collection
- query inventory bằng variant của workspace khác

Authorization phải kiểm tra ownership server-side, không dựa vào ID frontend gửi lên.


# 16. Archive semantics

Giữ nguyên nguyên tắc archive thay vì hard delete đối với entity business quan trọng.

Locations:
- archive/deactivate thay vì xóa dữ liệu inventory/history.

Collections:
- có thể archive.

Products/variants:
- giữ semantics archive F2.

Không cascade hard-delete inventory/history một cách vô tình.

# 21. Acceptance criteria

1. Product thuộc workspace, không thuộc location.

2. Một product/variant chỉ tồn tại một lần trong master catalog dù được bán tại nhiều locations.

3. Workspace có thể có nhiều locations.

4. Một location có thể bán một subset của workspace catalog.

5. Hai locations có thể cùng bán một variant.

6. Một location có thể không bán variant mà location khác đang bán.

7. Inventory được lưu theo `(location_id, variant_id)`.

8. `quantity = null` và `quantity = 0` tiếp tục có semantics khác nhau.

9. Cùng một variant có thể có inventory khác nhau tại từng location.

10. Variant có base price dùng chung.

11. Location có thể override giá mà không thay đổi base price.

12. Nếu không có override thì effective price sử dụng base price.

13. Variant availability tại location không yêu cầu duplicate product.

14. Product có thể nằm trong nhiều collections.

15. Catalog search hỗ trợ filter theo location thuộc workspace.

16. Catalog search hỗ trợ filter theo collection thuộc workspace.

17. Location filter chỉ trả variant active tại location đó.

18. Collection filter chỉ trả product thuộc collection đó.

19. Tenant isolation được enforce cho locations, collections, products, variants và inventory.

20. F2.1 import vẫn tạo master product/variant đúng semantics.

21. Import location data không duplicate product theo location.

22. Existing variant stock được migrate sang default location mà không làm mất `null` vs `0`.

23. Preview/search/API/UI đều dùng cùng source of truth cho inventory và effective price.

24. Archive location không làm mất master product hay lịch sử dữ liệu.

25. Không hardcode domain theo thời trang hoặc một ngành hàng cụ thể.


# 22. Regression tests bắt buộc

Test ít nhất:

- cùng variant tại hai locations với stock khác nhau
- cùng variant tại hai locations với price override khác nhau
- location A bán variant, location B không bán
- base price fallback khi không có override
- null stock khác zero stock
- location filter không đọc inventory location khác
- collection scope giới hạn đúng product
- cùng product thuộc nhiều collections
- cross-workspace product/location assignment bị từ chối
- migration stock cũ giữ nguyên null/0/value
- archive location không archive product
- F2.1 import không duplicate product theo location

    workspace + location/collection scope.

12. Làm API.

13. Làm UI Locations / Collections.

15. Chạy migration/test/lint/typecheck.

16. Cập nhật ADR, API contract, schema docs và README.

17. Chỉ commit khi toàn bộ acceptance criteria liên quan đã đạt.


# 25. Nguyên tắc kiến trúc cuối cùng

Workspace owns the master catalog.

Product and variant represent shared catalog identity.

Location represents where a variant is sold.

Inventory belongs to location + variant.

Variant owns the default/base price.

Location may override commercial data such as price.

Collections organize subsets of the workspace catalog.

Không duplicate product theo chi nhánh.
Không đặt stock toàn workspace trực tiếp trên product.
