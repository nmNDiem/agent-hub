
# F2 — Universal Catalog Import & Generic Catalog Architecture

## 1. Mục tiêu

Nâng cấp F2 từ catalog thời trang + CSV importer cố định thành một **catalog engine đa ngành** có khả năng:

- quản lý product/variant/image/options/attributes theo workspace;
- nhập catalog từ CSV, XLS và XLSX;
- tự hiểu cấu trúc file thay vì yêu cầu người dùng chọn nguồn hoặc map toàn bộ cột;
- hỗ trợ các file export từ Sapo, Shopify, WooCommerce, ERP, Excel thủ công hoặc các hệ thống khác mà không viết parser riêng theo vendor;
- xử lý product row, variant row, image continuation row, metadata row và các cấu trúc bảng thực tế;
- lưu ambiguity để user chỉ xác nhận những điểm thật sự chưa rõ;
- preview chính xác create/update/unchanged/conflict trước commit;
- import atomic và idempotent;
- hỗ trợ generic options để catalog không bị hardcode cho thời trang;
- cung cấp structured catalog search cho chatbot.

Nguyên tắc kiến trúc quan trọng:

> Importer nhận diện cấu trúc dữ liệu, không nhận diện vendor để chọn parser.

Không có các branch kiểu:

```python
if source == "sapo":
    ...
elif source == "shopify":
    ...
```

Mapping đã học từ một cấu trúc file có thể được tái sử dụng, nhưng vendor không phải abstraction của importer.

# 4. Acceptance criteria tổng thể

F2 chỉ được xem là hoàn thành khi đáp ứng tất cả các tiêu chí sau.

## File formats

- CSV.
- XLS.
- XLSX.
- Cả ba đi qua cùng logical pipeline:

```text
Extract
→ Profile
→ Resolve Schema
→ Resolve Structure
→ Normalize
→ Stage
→ Validate
→ Resolve Identity
→ Diff
→ Commit
```

Không tồn tại importer logic riêng theo vendor.

## Catalog

Hỗ trợ:

- products;
- variants;
- generic options;
- product attributes;
- variant attributes;
- images;
- external references;
- pricing;
- compare-at pricing;
- inventory;
- inventory policy;
- descriptions;
- size guide compatibility.

## Import semantics

Phân biệt chính xác:

```text
MISSING
VALUE
BLANK
EXPLICIT_NULL
ZERO
FALSE
```

Không collapse missing/null/blank thành cùng một giá trị.

## Ambiguity

Ambiguity:

- được persist;
- có machine-readable reason;
- có evidence;
- có possible resolutions;
- user chỉ resolve những ambiguity cần thiết;
- không cần map toàn bộ file.

## Mapping memory

Mapping memory vẫn hoạt động khi:

- reorder columns;
- capitalization thay đổi;
- whitespace thay đổi;
- optional columns thêm/bớt;
- filename thay đổi.

Không dùng filename làm identity của mapping.

## Commit

Commit phải:

- atomic;
- idempotent;
- workspace-scoped;
- revalidate identity;
- revalidate SKU uniqueness;
- revalidate affected records;
- rollback toàn bộ nếu có lỗi.

## Search

Khi query nhiều option:

```text
Color = Red
Size = L
```

phải tồn tại **một actual variant** có cả hai.

Không được match:

```text
Variant A = Red + M
Variant B = Blue + L
```

thành Red + L.

## Compatibility

API catalog cũ phải tiếp tục hoạt động trong F2.

## Testing

Các behavior quan trọng về:

- JSONB;
- transaction;
- uniqueness;
- tenant isolation;
- generic options;
- import staging;
- concurrency;

phải có PostgreSQL integration tests.

SQLite không được coi là đủ cho các test đó.

```text

```

Nhưng generic options là source of truth.

Quy tắc:

### Read

Nếu API cũ đọc `color` hoặc `size`, compatibility adapter lấy từ generic options:

```text
Color
Size
```

Legacy columns chỉ có thể dùng fallback trong migration phase.

### Write

Nếu API cũ gửi:

```json
{
  "color": "Red",
  "size": "L"
}
```

backend phải chuyển thành generic option mutations trong cùng transaction.

Không được có hai independent sources:

```text
variant.color = Red
generic Color = Blue
```

Migration phải backfill legacy data thành generic option data.

## Remote image security

F2 importer không được tự ý fetch arbitrary remote URL trong analyze/commit.

Import chỉ:

- validate URL syntax;
- chỉ chấp nhận HTTP/HTTPS;
- lưu `source_url`.

Nếu tương lai có downloader riêng, downloader phải chống SSRF:

- localhost;
- loopback;
- RFC1918/private network;
- link-local;
- cloud metadata endpoints;
- unsafe redirect chains;
- non-http schemes.

## External identity invariant

Không sử dụng raw `external_id` làm identity nếu namespace không đáng tin cậy.

Ví dụ:

```text
product_id = 123
```

không đủ.

Phải là:

```text
namespace = some-confirmed-source
external_id = 123
```

Namespace chỉ được coi là trusted khi có evidence như:

- connector đã xác định;
- import mapping profile đã được user xác nhận;
- persisted mapping đã được xác nhận từ import trước.

Không đoán vendor chỉ để tạo namespace.

Nếu namespace chưa rõ:

```text
external_id
```

được lưu làm import evidence hoặc custom attribute nhưng không dùng làm identity.

# 11. Product identity resolution

Identity priority:

```text
1. Agent Hub canonical entity ID
2. Trusted namespaced external reference
3. Workspace-scoped SKU
4. Explicitly confirmed grouping/identity from current import
5. Conflict / needs confirmation
```

Không identity merge bằng:

- product name;
- fuzzy name;
- semantic similarity;
- AI similarity;
- description similarity.

Ví dụ hai product cùng tên:

```text
Basic T-Shirt
```

không được tự merge.

# 12. SKU rules

SKU uniqueness phải giữ trong cùng workspace theo behavior hiện tại.

Nếu product/variant SKU namespace dùng chung thì giữ một constraint chung.

Nếu schema hiện tại phân tách, cần document rõ rule và giữ backward compatibility.

Import phải normalize SKU tối thiểu:

- trim;
- preserve meaningful casing trừ khi business rule hiện tại nói khác;
- blank → no SKU;
- không tự sinh SKU.

Không AI-generate SKU.

# 13. Import mode

Default import mode:

```text
MERGE
```

Semantics:

> Chỉ những entity/field có trong file mới có khả năng create/update. Entity không xuất hiện trong file không bị archive/delete.

Ví dụ catalog có 1.000 product, file chỉ có 50:

→ 950 product còn lại giữ nguyên.

Không bao giờ hiểu absence là delete mặc định.

Có thể chuẩn bị architecture cho future:

```text
FULL_SNAPSHOT
```

nhưng nếu chưa có UX hoàn chỉnh thì không expose ở F2.

Nếu sau này implement FULL_SNAPSHOT, preview phải hiển thị rõ:

```text
Create
Update
Unchanged
Archive because absent from snapshot
```

và cần explicit confirmation.

# 14. Cell-state semantics

Ngay từ extraction/staging phải giữ trạng thái field.

Không dùng:

```python
dict[str, Any | None]
```

nếu làm mất distinction.

Logical representation:

```text
MISSING
VALUE(x)
BLANK
EXPLICIT_NULL
```

Trong đó:

```text
VALUE(0)
VALUE(False)
```

vẫn là value thực.

## Update semantics

### MISSING

File không nói gì về field.

Khi update entity hiện có:

```text
KEEP EXISTING VALUE
```

### VALUE(x)

Set thành `x`.

### ZERO

Là value thật:

```text
stock_quantity = 0
```

nghĩa là hết hàng.

### BLANK

Không mặc định coi là delete.

Tùy field policy có thể:

- normalize thành empty;
- ignore;
- require confirmation;
- explicit clear nếu mapping/profile xác định như vậy.

### EXPLICIT_NULL

Chỉ clear field nếu source format/mapping có reliable explicit-null semantics.

Delete intent phải explicit trong staging.

# 16. Price semantics

Product có:

```text
base_price
compare_at_price
```

Variant có thể override:

```text
price
compare_at_price
```

Rule:

```text
effective variant price =
variant.price if defined
else product.base_price
```

Missing variant price khi update không được xóa override cũ.

Explicit clear phải được biểu diễn riêng.

Currency không được suy đoán tùy tiện nếu source không có và workspace không có default rõ ràng.

## Schema fingerprint

Không dùng filename.

Fingerprint dựa trên combination của:

```text

inferred column types
sheet structure
column relationships

```

Fingerprint phải insensitive với:

- reorder columns;
- case;
- whitespace;
- optional columns.

Không nhất thiết hash raw headers theo thứ tự.

Có thể dùng matching score giữa profile hiện tại và saved mapping profile.

Chỉ auto-apply saved mapping khi confidence vượt threshold an toàn.

Nếu thấp hơn → evidence cho resolver, không coi là truth.

# 26. AI fallback

AI chỉ dùng khi deterministic + saved mapping + structural inference chưa đủ.

Dùng OpenAI Structured Outputs qua adapter riêng.

AI input chỉ chứa dữ liệu tối thiểu cần thiết:

- headers;
- representative samples;
- inferred types;
- neighboring columns;
- distributions/summary;
- structural evidence.

Không gửi toàn bộ workbook nếu không cần.

AI output phải validate bằng Pydantic.

## AI không được phép

AI không được:

- ghi DB;
- tạo product;
- tạo variant;
- quyết định upsert;
- quyết định hai entity là cùng product dựa trên semantic similarity;
- tự sinh missing business data;
- invent SKU;
- invent prices;
- invent stock;
- silently resolve destructive actions.

AI chỉ cung cấp schema interpretation/evidence.

Timeout, 429, invalid output hoặc API unavailable:

→ import vẫn tiếp tục.

Những mapping không đủ certainty:

```text
NEEDS_CONFIRMATION
```

Không fail toàn import chỉ vì AI unavailable.

Tests dùng fake AI adapter.

Real OpenAI API không phải CI dependency.

Phân loại row thành các logical roles:

```text

VARIANT
IMAGE_CONTINUATION
ATTRIBUTE_CONTINUATION

```

```text

     |       |        | image2
     |       |        | image3
```

Các dòng sau có thể được classify thành `IMAGE_CONTINUATION` khi:

```text

+
```


- relational workbook structure;
- confirmed mapping;
- structural row continuation.

# 29. CatalogNormalizer

Normalizer chuyển raw resolved data thành canonical staged model.

- parse stock;

- resolve attributes;

- normalize images;

# 30. Option signature

Mỗi variant có deterministic normalized option signature.

Ví dụ:

```text
Color=red|Size=l
```

Nhưng implementation phải tránh phụ thuộc presentation order.

Signature dùng normalized option-definition identity + normalized value.

Có thể dùng hash/canonical JSON.

Mục đích:

- detect duplicate variant option combinations;
- stable diff;
- data integrity.

Không thay SKU bằng option signature.

# 34. Analyze vs Commit

## Analyze

Analyze:

- extract;
- profile;
- resolve;
- stage;
- validate;
- identity resolution;
- diff.

Không mutate canonical catalog.

## Resolve

Resolve:

- lưu user decision;
- rerun affected pipeline stages;
- regenerate diff.

Không cần analyze lại toàn file nếu chỉ một issue thay đổi, nếu architecture cho phép incremental recompute.

## Commit

Commit:

- chạy DB transaction;
- lock/re-read affected identities;
- revalidate affected records;
- enforce constraints;
- mutate canonical catalog;
- mark import committed.

Nếu lỗi:

```text
ROLLBACK ALL
```

# 35. Concurrency strategy

Không reject import chỉ vì bất kỳ record nào trong catalog thay đổi.

Có thể lưu:

```text

```

cho audit/debug.

Nhưng commit conflict phải kiểm tra affected scope:

- matched products;
- matched variants;
- SKUs;
- external refs;
- option identities;
- relevant uniqueness assumptions.

Ví dụ user khác sửa Product Z không liên quan:

→ import Product A không nên fail.

Nếu Product A hoặc SKU liên quan thay đổi:

# 36. Idempotency

Commit cùng import job hai lần không được duplicate data.

Nếu job đã:

```text

```

subsequent commit:

- trả committed state hiện tại;
- không chạy mutation lần hai.

Ngoài job idempotency, identity constraints phải ngăn duplicate canonical records.

# 74. Commit

Sau khi toàn bộ verification hợp lệ:

Tạo một Conventional Commit duy nhất cho F2 nếu kích thước/repository workflow vẫn phù hợp.

Ví dụ:

```text
feat(catalog): add universal catalog import pipeline
```

Commit body ghi rõ:

- generic options;
- universal CSV/XLS/XLSX import;
- staging/diff/atomic commit;
- mapping memory;
- PostgreSQL integration tests;
- compatibility behavior.

Không include:

```text
apps/web/next-env.d.ts
```

nếu đó vẫn là pre-existing user change không thuộc task.

# 75. Quy tắc khi triển khai bằng Codex

Trước khi code:

1. Audit code/docs hiện tại.
2. Reconcile plan này với conventions đang có.
3. Không thay đổi các invariant của plan chỉ vì implementation hiện tại đơn giản hơn.
4. Nếu tên table/API cần đổi để hợp convention thì được phép, nhưng semantics không đổi.
5. Không dừng lại sau từng phase để hỏi user nếu không có blocker thực sự.
6. Hoàn thành toàn bộ F2, tests, docs và verification.
7. Không tự thu nhỏ scope thành CSV-only hoặc fashion-only.
8. Không thêm vendor-specific parser.
9. Không dùng AI để che thiếu deterministic architecture.
10. Không claim hoàn thành khi PostgreSQL integration tests chưa chạy.

Nếu phát hiện conflict thực sự giữa plan này với schema/code hiện có, ưu tiên:

```text
data integrity
backward compatibility
tenant security
generic architecture
user UX
```

và chọn implementation phù hợp nhất mà không phá các invariant trên.
